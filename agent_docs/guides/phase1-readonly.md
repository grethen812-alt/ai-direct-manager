# AI Direct Manager — запуск первой фазы

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `phase1_readonly.py` | Команда запуска первой фазы, список инструментов, проверка кабинета и счётчика, контроль исходящих HTTP-запросов |
| `phase1_reports.py` | Ограничения времени, периода, строк и байтов, проверка формата отчётов |
| `phase1_demo.py` | Отдельный синтетический сервер для проверки MCP без доступа к Яндексу |
| `server.py` | Основной MCP-сервер и общие обработчики Директа |
| `tools_metrika.py` | Общие схемы и обработчики Метрики |
| `tools_direct_extra.py`, `tools_audience.py` | Дополнительные возможности основного сервера |
| `requirements.txt`, `pyproject.toml` | Зафиксированные версии зависимостей, сборка и команды запуска |
| `test_phase1_readonly.py`, `test_phase1_reports.py`, `test_safety.py` | Синтетические сценарии первой фазы и проверки основного сервера |

## Установка и запуск

Нужен Python 3.10 или новее. Из корня репозитория выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install --no-deps .
python -m pip check
```

В настройках локального MCP-клиента укажите транспорт `stdio` и абсолютный путь к
`.venv/bin/yandex-ads-mcp-phase1`. Для запуска из исходников можно указать путь к
`.venv/bin/python` и передать абсолютный путь к `phase1_readonly.py` первым аргументом.
Сервер общается с клиентом по стандартному вводу и выводу. При корректной настройке
он ждёт команды MCP.

## Настройка окружения

Передайте переменные процессу через настройки MCP-клиента или окружение запуска.
Python-процесс читает переменные окружения. Файл `.env` автоматически не загружается.
Храните секретные значения вне Git и переписки.

| Переменная | Обязательность | Значение |
| --- | --- | --- |
| `YD_OAUTH_TOKEN` | Да | OAuth-токен Директа для отдельного представителя с правом «Только чтение» |
| `YD_METRIKA_TOKEN` | Да | Отдельный OAuth-токен с разрешением `metrika:read` и доступом «Только просмотр» |
| `YD_PHASE1_DIRECT_CLIENT_ID` | Да | Числовой `ClientId` разрешённого кабинета Директа |
| `YD_PHASE1_METRIKA_COUNTER_ID` | Да | Числовой ID разрешённого счётчика |
| `YD_LOGIN` | Для агентского вызова | Фиксированный `Client-Login` выбранного рекламодателя. Для токена прямого рекламодателя оставьте пустым |

Для этого процесса режим чтения включён постоянно, в том числе при
`YD_READONLY=false` и `YD_CONFIRM=true`. Профиль использует фиксированные адреса
двух API. Переменные основного сервера для дополнительных кабинетов, альтернативного
адреса API, песочницы и подробных журналов на профиль не влияют.

## Разрешённые операции

| Инструмент MCP | Операция API |
| --- | --- |
| `yd_campaigns_get` | Директ `campaigns.get` |
| `yd_adgroups_get` | Директ `adgroups.get` |
| `yd_ads_get` | Директ `ads.get` через v501 |
| `yd_keywords_get` | Директ `keywords.get` |
| `yd_report` | Директ `POST /json/v5/reports`, получение TSV с опросом готовности |
| `yd_metrika_counter_get` | Метрика `GET /management/v1/counter/{id}` |
| `yd_metrika_goals_get` | Метрика `GET /management/v1/counter/{id}/goals` |
| `yd_metrika_report` | Метрика `GET /stat/v1/data` |

Перед каждым разрешённым вызовом Директа профиль отдельно запрашивает только
`ClientId` через `Clients.get`. При несовпадении с настройкой запрос данных
не выполняется. Этот служебный запрос не опубликован как MCP-инструмент.
Аргумент `client_login` запрещён. В Метрике аргумент `counter_id` должен совпадать
с настройкой как при вызове MCP, так и в исходящем запросе. Профиль не следует
за HTTP-перенаправлениями и не использует прокси из окружения.

Ошибки инструментов передаются без исходного ответа API, аргументов и значений
переменных. Протокольные и HTTP-журналы отключены при запуске профиля.

## Ограничения отчётов

| Ограничение | Значение и причина |
| --- | --- |
| Общий срок | **90 секунд** для каждого отчёта. В Директе сюда входят проверка кабинета, запросы, ожидание и чтение ответа. Из общего бюджета туннеля в 120 секунд остаётся до 30 секунд для очереди и доставки. |
| Ожидание в Директе | От **1 до 5 секунд** между опросами Reports. Если API прислал некорректный интервал или не прислал его, используется 5 секунд. Пауза повторного запроса проверки кабинета также ограничена 5 секундами. |
| Период | До **31 календарного дня включительно**, чтобы охватить календарный месяц. Даты принимаются в формате `YYYY-MM-DD`. В Метрике по умолчанию используются последние 30 дней включительно по Москве, а при заданной только дате окончания отсчёт идёт от неё. |
| Строки | До **1 000 строк** на отчёт. Это позволяет запросить месячный срез по примерно 30 группам в разбивке по дням. В Метрике можно уменьшить лимит, по умолчанию он равен **100**. |
| Объём | До **128 КиБ** тела ответа и текста, возвращаемого инструментом. Это ограничивает объём данных для модели и защищает от больших ответов с длинными значениями. |

Директ проверяет UTF-8 TSV, заголовок с запрошенными колонками и число колонок в строках.
Служебные строки с названием и итоговым счётчиком отключены, заголовок колонок остаётся.
Метрика проверяет JSON, форму строк и соответствие фактического числа строк значению
`total_rows`. Если полноту нельзя подтвердить из-за округления или неполного ответа,
инструмент возвращает ошибку. Флаг семплирования сохраняется в корректном отчёте.

Сервер запрашивает на одну строку больше лимита, чтобы заметить переполнение.
Превышение любого ограничения возвращает ошибку MCP без частичного отчёта.
Для большого отчёта сузьте период, добавьте фильтр или уменьшите набор полей.

[Бюджет запроса Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels#limits) ·
[Формат отчётов Директа](https://yandex.ru/dev/direct/doc/ru/report-format) ·
[Формат отчётов Метрики](https://yandex.ru/dev/metrika/ru/stat/openapi/data_1)

## Синтетический сервер и Secure MCP Tunnel

В виртуальном окружении запустите синтетический профиль одной командой:

```bash
yandex-ads-mcp-phase1-demo
```

Из исходников можно выполнить `python phase1_demo.py`. Профиль автоматически использует
синтетические учётные данные, кабинет `101` и счётчик `202`. HTTP подменяется в памяти.
Команда ждёт MCP-сообщения на стандартном вводе и пишет ответы в стандартный вывод.

Для частного туннеля укажите абсолютный путь к
`.venv/bin/yandex-ads-mcp-phase1-demo` в поле команды запуска `stdio` в профиле
`tunnel-client`. После обновления кода переустановите пакет и перезапустите клиент
туннеля, чтобы он запустил новую версию MCP-процесса.
В браузерном Codex вызовите `yd_metrika_report` для счётчика `202` с метрикой
`ym:s:visits`. Ожидаемый результат — **9 визитов** и `total_rows: 1`.
Для отрицательной проверки задайте этому же инструменту `limit: 1001`.
Ожидается ошибка лимита без данных отчёта.

## Офлайн-проверки

В активированном виртуальном окружении выполните:

```bash
python test_safety.py
python -m unittest -v test_phase1_readonly test_phase1_reports
python -m pip wheel --no-deps . --wheel-dir dist
```

`test_phase1_readonly.py` запускает MCP-процесс через `stdio`. Ответы Директа и Метрики
подменяются в HTTP-транспорте. В тестах есть синтетический TSV, отчёт Метрики,
кампании, группы, объявления, фразы и цели. Для всех проверок используются
вымышленные идентификаторы и учётные данные.
